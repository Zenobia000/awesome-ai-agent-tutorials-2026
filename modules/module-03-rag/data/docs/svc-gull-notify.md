# gull-notify 通知服務說明

> 服務：gull-notify｜類型：服務說明｜版本：v2.3.0｜負責團隊：會員組｜更新：2026-10-10

## 這個服務做什麼

gull-notify 負責發送簡訊、Email 與 App 推播。其他服務不直接呼叫簡訊商，而是把通知請求丟到
current-mq 的 `hf.notify.request.v2`，由 gull-notify 消費後發送。

## 通道與供應商

- 簡訊：主要供應商代號 `sms-p1`，失敗時自動改走 `sms-p2`。每日簡訊額度 200,000 則。
- Email：自建 SMTP 轉送，每小時上限 50 萬封。
- 推播：透過 App 推播服務，無額度限制。

## 範本

所有通知都必須用事先登記的範本，範本 id 格式 `TPL-<領域>-<編號>`，例如 `TPL-ORDER-003`（出貨通知）。
新增範本要在後台登記並經會員組審核，約需 1 個工作天。

## 錯誤碼

| 錯誤碼 | 意思 | 處理方式 |
|---|---|---|
| NTF-601 | 找不到範本 | 範本 id 打錯或尚未審核通過 |
| NTF-602 | 當日簡訊額度用完 | 非緊急簡訊延到隔天 00:05 送；緊急可找會員組主管臨時加額度 |
| NTF-610 | 收件人號碼格式錯誤 | 丟棄，不重試 |
| NTF-620 | 兩家簡訊商都失敗 | SEV2，通知值班 |
