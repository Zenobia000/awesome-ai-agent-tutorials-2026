# Runbook：TP-5003 收單行連線失敗與切換備援

> 服務：tide-pay｜類型：runbook｜版本：v3.4.2｜負責團隊：金流組｜更新：2026-08-20

## 症狀

- 付款 API 錯誤率上升，日誌大量出現 `TP-5003`。
- 監控面板「收單行健康度」中 `acq-a` 轉紅。

## 判斷

1. 先確認是不是只有單一收單行出問題：執行 `hfctl tidepay acquirer-status`。
2. 如果 `acq-a` 失敗率超過 20% 且持續 3 分鐘以上，就要切換。
3. 如果兩家都失敗，問題多半在我們自己的出口網路，改查 egress 閘道，不要切換。

## 切換步驟

1. 在值班頻道宣告 SEV2，說明要切換收單行。
2. 執行 `hfctl tidepay failover --to acq-b`。這個指令需要第二位值班人員核准，系統會發核准請求。
3. 觀察 5 分鐘：TP-5003 應該降到每分鐘 10 筆以下。
4. acq-b 每秒處理上限是 400 筆交易，大促期間可能不夠，要同時通知營運考慮限流。

## 切回

`acq-a` 恢復正常 30 分鐘以上，再執行 `hfctl tidepay failover --to acq-a`。切回同樣需要第二人核准。
不要在請款批次（02:30～03:30）期間切換。
