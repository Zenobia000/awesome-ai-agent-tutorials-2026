MCP：三個老想法，換了舞台

你學過的交換格式、裝置抽象、計算圖，幾乎能直接接過來。

你已經會的ONNX：框架 × 推論引擎若各寫轉換器就寫不完，所以共用一種交換格式。
本章的新概念MCP：AI 應用 × 工具若各寫接頭就寫不完，所以共用一個協定。
你已經會的PyTorch 把模型定義和 device 分開：同一張計算圖，放 CPU 或 GPU 都行。
本章的新概念MCP 把資料層（JSON-RPC 訊息）和傳輸層（stdio、HTTP）分開：同一份訊息，走不同管道。
你已經會的靜態圖路徑固定、好部署；動態圖（eager）每次依輸入決定走哪個分支。
本章的新概念Dify／n8n 的畫布是固定流程；LangGraph 的 agent 依狀態決定下一步。
怎麼讀：左邊是你已經熟的，右邊是本章對應的新東西；三條線就是本章三個重點。
