Tool calling 的真面目

模型不會執行函式，它只「寫出」一段 JSON；真正去跑函式的，是你的程式。

{"role": "user", "content": "USB-C 轉接器多少錢？"}
{"role": "assistant", "tool_calls": [ {"id": "call_1", "type": "function", "function": { "name": "get_price", "arguments": "{\"item\": \"USB-C 轉接器\"}"}}]}
{"role": "tool", "tool_call_id": "call_1", "content": "{\"price\": 350, \"currency\": \"TWD\"}"}
{"role": "assistant", "content": "USB-C 轉接器 350 元。"}
使用者問
問題，外加工具清單：名稱、說明、參數格式
模型回覆（只是 token）
不是答案，是一段符合 schema 的 JSON。它的最後一層仍是 softmax，只是被微調成會吐這種格式；它沒執行任何東西。
你的程式
解析 JSON、真的呼叫 get_price，回傳值包成 tool 訊息，用 id 配對。
模型回覆
讀完整串訊息，這次直接寫文字答案。
示意　格式是真的（OpenAI 相容 Chat Completions，Ollama 端點也吃這種）；商品與價格是編的。
怎麼讀：由上往下四則訊息；方＝使用者資料、圓＝模型、三角＝你的程式去做事。標黃的 id 是同一次呼叫的配對。
