踩坑：死循環燒 token、並發寫入出錯

兩個最常見的事故，每個都是：看到什麼 → 為什麼 → 怎麼改。

症狀
原因
修法
死循環、token 耗盡同一個工具被反覆呼叫，帳單一直跳，agent 停不下來。
工具回傳的格式不是模型預期的，它不斷重試；而 recursion_limit 預設 10,007，等於沒有保險。
{"recursion_limit": 25}
放在 config 頂層，明確設小值；再用 ToolCallLimitMiddleware 限制呼叫次數。
並發寫入出錯兩個平行節點寫 results，直接拋 InvalidUpdateError。
沒有 reducer 的欄位，同一步只能一個寫入者；分先後寫則後者覆蓋前者。
Annotated[list, operator.add]
用 reducer 明講「追加」。messages 欄位改用 add_messages。
怎麼讀：每一列由左往右。紅格是你會在 log 或帳單看到的，藍格是要改的那一行。
