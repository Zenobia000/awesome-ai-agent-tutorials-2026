Agent 設計模式（二）：交給模型決定

步數預估不出來，才讓模型自己決定；多個 agent 協作時，差別在「誰握著控制權」。

模式誰決定下一步一句話什麼時候選它代價
ReAct／工具呼叫迴圈docs.langchain.com模型想 → 呼叫工具 → 看結果，重複開放式問題、步數無法預估錯誤會累積；要設上限
Plan-and-executedocs.langchain.com模型（規劃者）先列計畫，再逐步執行長任務，要讓人看得到進度計畫可能過時
Subagents（子 agent 當工具）docs.langchain.com主 agent開乾淨 context 去查，只回摘要隔離 context、平行查證每次都經主 agent 轉手
Handoffsdocs.langchain.com現任 agent用工具把控制權交給下一位使用者要直接和專員對話訊息歷史容易膨脹
Skillsdocs.langchain.com模型需要時才載入專業提示與知識同類請求重複出現載入內容留在 context 裡
Custom workflowdocs.langchain.com混合確定性節點和 agent 節點混一張圖要精準控制開發維護成本最高
不要按職能切（文件 agent／資料庫 agent…）。LangChain 官方比較：同一請求 Subagents 要 4 次模型呼叫，其他各 3 次。　核實 2026-11-17
怎麼讀：上兩列是單一 agent，下四列是多個 agent 或能力怎麼分工；本課 Lab 5 用的是紅字兩種。
