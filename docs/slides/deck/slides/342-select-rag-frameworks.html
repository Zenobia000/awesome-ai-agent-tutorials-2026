選型：RAG 框架與平台

框架負責把「切分 → 入庫 → 檢索 → 組提示詞」串起來；差別在重心放在哪裡。

名稱定位什麼時候選它授權／狀態
LangChain本課用docs.langchain.com整合生態＋Agent 外殼要大量整合，之後還要接 LangGraphMIT；1.x 起舊 retriever 移到 langchain_classic
LlamaIndexgithub.com/run-llama/llama_index以資料與索引為中心重點在文件解析、切分、索引策略MIT；公司重心已轉向 LlamaParse
Haystackgithub.com/deepset-ai/haystack元件化、可控的生產管線要型別清楚、好測試的正式環境 pipelineApache-2.0；已進 3.x
RAGFlowgithub.com/infiniflow/ragflow開箱即用的 RAG 平台不寫程式，要 Web UI 與深度文件解析Apache-2.0；Docker 部署，吃記憶體
框架不是必需品：本課 Lab 3 的核心邏輯（BM25、RRF、重排）都是自己寫的，框架只負責串接。　核實 2026-11-17
怎麼讀：上面三個是寫程式用的框架，最後一個是平台；先決定要不要寫程式，再挑重心符合的那個。
