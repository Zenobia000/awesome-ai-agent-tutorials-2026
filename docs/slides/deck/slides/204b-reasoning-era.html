推理模型：不教怎麼想，定義成功

「先想再答」已經被訓練進推理模型；提示詞的重心改成寫清楚怎樣算對。

一般模型：教它怎麼想
你是 SQL 專家。 請一步一步想： 1. 先找出需要的資料表 2. 再決定 JOIN 順序 3. 最後寫出 SQL
步驟是你替模型想好的，它照你的路走。對推理模型，這句「一步一步想」不必要，甚至可能有害。
推理模型：定義怎樣算對
目標：回答問題的單一 SELECT。 成功條件： - 只用 schema 中存在的欄位 - 結果欄位名稱對應問題的用語 - 問題不明確就回報 unclear
路徑讓模型自己找。條件寫清楚，程式才有東西可以拿來檢查它交出的結果。
你已經會的訓練前要先定義 loss。提示詞也一樣：先把「對」的標準寫清楚，再讓模型去找路徑。
例外：DeepSeek-R1 distill官方建議不放 system prompt，指令全放 user，溫度設 0.5–0.7。角色設定也寫進 user。
怎麼讀：兩份提示詞要的是同一個結果；左邊規定過程，右邊規定驗收標準，推理模型只需要後者。
