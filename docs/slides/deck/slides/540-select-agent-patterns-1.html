Agent 設計模式（一）：Workflow 五式

路徑大多由程式決定；能用這五種解決，就先別上自主 agent。

模式誰決定下一步一句話什麼時候選它代價
Prompt chainingwww.anthropic.com程式固定步驟串接，中間設檢查能拆成固定子任務延遲疊加；前錯後錯
Routingdocs.langchain.com模型分類，程式分派先分類，再交給專責流程類別清楚、各類要不同處理分錯類就全錯
Parallelizationdocs.langchain.com程式子任務同時跑，或跑多次投票子任務獨立、要速度或信心token 隨分支數倍增
Orchestrator-workersdocs.langchain.com模型拆題，程式扇出中央模型拆任務、派工、彙整事先不知道要拆成哪些子任務拆題品質決定成敗
Evaluator-optimizerwww.anthropic.com程式管迴圈，模型評分一個寫、一個評，改到通過評分標準明確每輪多一次推論
名稱與分法出自 Anthropic〈Building effective agents〉；LangGraph 文件有每一種的實作。　核實 2026-11-17
怎麼讀：看第二欄：越多「程式」越好測、越便宜；對回「Workflow 還是 Agent」那頁的原則——先用最簡單的。
