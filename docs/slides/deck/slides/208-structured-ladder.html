結構化輸出：三層保障，層層補洞

三層疊著用，不是三選一：每一層補上一層會漏掉的東西。

仍會失敗：
多吐說明、Markdown 外框
仍會失敗：
模型拒答、輸出被截斷
仍會失敗：
驗證不過：重試或報錯，不能放行
1　提示要求
在提示詞寫「只輸出 JSON」，靠模型自覺。
保證：沒有
2　原生結構化輸出
schema 編成文法，解碼時不合法的 token 被遮掉。tool calling 是同一機制。
保證：完成時符合 schema
3　Pydantic 驗證
解析後再查型別、範圍、業務規則：schema 表達不了的限制，在程式端擋。
保證：程式收到的必定過驗證
實物：被截斷的輸出
stop_reason: max_tokens {"sql": "SELECT SUM(am
不是合法 JSON，也不符合 schema。格式保證只在「完成且沒拒答」時成立，所以要檢查 stop_reason。
三家都有原生支援：
OpenAI　json_schema
Anthropic　output_config.format
Ollama　format 參數
你已經會的約束解碼＝每一步把不合法 token 的機率遮成 0 再 softmax，和 attention mask 設 −∞ 是同一招。
怎麼讀：階梯越高保證越強，方塊上方朱紅字是那一層仍會漏掉的情況；三層疊起來用。
