多 agent 何時值得拆：實測三種拆法

同一題「下單一直 502，找根因」用 CrewAI 做三版。三版都找對根因，差在花多少、資訊轉手幾次。

總 tokens 本課實測
1,356
13,212
14,116
A 單一 agent1 個 agent・2 次請求
B 依角色硬拆4 個 agent・28 次請求
C 平行查證＋審查4 個 agent・28 次請求
A：問題小、工具少，一個就夠
先用一個 agent，有證據不夠用才拆。
B：依職能切，是反模式
主管看不到原始資料，只能信三份摘要；任何一份抄錯，結論跟著錯。
C：一樣貴，但買到東西
每條線索同時查、各自 context 乾淨，再由審查者挑沒有證據的結論。
本課實測：CrewAI＋本機 qwen2.5:3b，跑一次；B 約 A 的 9.7 倍、C 約 10.4 倍，重跑會略有不同。大型系統的倍數見「多 agent 的代價：token 約 15 倍」那頁。
怎麼讀：柱子越高越貴；右邊三段是「多花的 token 有沒有換到東西」。拆的理由見「什麼時候才切成多個 agent」那頁。
