什麼時候才切成多個 agent

切開的理由是 context、平行或權限，不是職能。先用一個 agent，有證據再切。

反模式：按職能切
主管 agent
文件 agent
資料庫 agent
運維 agent
「502 是不是資料庫慢？」要同時查文件和資料庫，
就得來回轉手；每轉一次，細節就掉一點。
值得切開的四種情況
隔離 context
要讀一大堆東西，交給子 agent 讀完只回摘要
平行查證
每個懷疑的原因開一個唯讀子 agent，同時跑
寫的和審的分開
產出的 agent 不該自己打分數
權限或組織邊界
不同部門的資料與權限不能共用
本課轉述　Anthropic（2026-01）：單一 agent 能處理大多數企業工作流程；多 agent 依「context 邊界」切，不依角色切
怎麼讀：左邊是常見的錯誤切法；右邊四種才是切開的好理由。對回「多 agent 的 token 代價」那頁：每多一個 agent，帳單就多一截。
