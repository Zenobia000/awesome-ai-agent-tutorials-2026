Workflow 還是 Agent？

步驟寫得出來，就寫成固定流程；答不出來，才讓模型自己決定。

Workflow
路徑寫死在程式裡：
好測、成本固定
分類
查資料
寫回答
答案
Agent
每輪由模型選工具，
或交出答案；
走幾輪不固定
查價
運算
交出答案
結果回來，再選一次
怎麼選
步驟事先寫得出來
→ workflow：便宜、快、好測
步驟數答不出來
→ agent：彈性大，但更貴、更慢、更難預測
原則：先用最簡單的，不夠再加複雜度。出自 Anthropic《Building effective agents》
你已經會的workflow 像靜態計算圖，每次走同一條路；agent 像 eager 模式，由資料決定 if／while 往哪走。
怎麼讀：上排箭頭是寫死的；下排圓（模型）每輪自己從出口挑一個——差別就在「誰決定下一步」。
