動手看看：一個 harness agent

不切成多個 agent：能力放進 skill 和工具，查證交給唯讀子 agent，重啟前要人點頭。

agent = create_deep_agent( model, tools=[read_logs, query_metrics, restart_service], system_prompt="你是值班 agent。", backend=FilesystemBackend(root_dir="./oncall"), skills=["/skills/"], # ops-runbook memory=["/AGENTS.md"], # 值班慣例 subagents=[log_checker], # 唯讀查證 interrupt_on={"restart_service": True}, checkpointer=InMemorySaver(), )
執行時的 trace 示意
agent → read_file …/ops-runbook/SKILL.md agent → task(log-checker) "DB 連線池？" agent → task(log-checker) "上游逾時？" ← "連線池用盡；證據：…；信心高" agent → restart_service("order-db-proxy") ⏸ 暫停，等值班主管審批
核准後恢復：Command(resume={"decisions": [{"type": "approve"}]})。沒列在 interrupt_on 的工具自動放行。
怎麼讀：左邊是組裝 agent 的全部程式，黃底三行是 harness 的三件外掛；右邊是一次執行，兩個查證平行跑，重啟停在審批。
